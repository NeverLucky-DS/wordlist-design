# Инструменты качества — что стоит и как этим пользоваться

Поставлено 2026-07-26. До этого в проекте не было **ни линтера, ни тайпчекера,
ни единого теста на фронт** — 7 824 строки HTML/CSS/JS проверялись только
глазами, а бэкенд только pytest'ом.

Ограничение, которое определило половину решений: **на машине нет Node**.
Поэтому весь фронтовый инструментарий здесь питоновский и живёт в том же `uv`,
что и бэкенд.

---

## Коротко: что делать руками, а что происходит само

| | когда | команда |
|---|---|---|
| ruff (gate `F`) | **само**, на каждую правку `.py` | `make lint` |
| ссылки на ассеты | **само**, на каждую правку фронта | входит в `make test` |
| подсказка про `?v=` | **само**, на правку css/js | — |
| спросить перед `docker restart` | **само** | — |
| проверка на выходе из сессии | **само** | — |
| тесты бэкенда | руками, обязательно после `backend/` | `make test` |
| визуальные снапшоты | руками, после правок вёрстки | `make visual` |
| фаззинг API | входит в `make test`; глубже — руками | `make fuzz` |
| типы | руками (и постоянно — через LSP в Claude Code) | `make types` |
| покрытие корпуса | руками, после вливания слов | `make coverage` |

## 1. ruff — линтер

**Gate — только `F`** (неиспользуемое, неопределённое, недостижимое). Полный
набор из `pyproject.toml` (`E,F,W,I,B,UP`) даёт на этом коде **160 замечаний**,
из них 30 «несортированные импорты» и 29 «старый `Optional`». Gate на 160
сделал бы CI красным в день установки, поэтому полный набор идёт в CI
информационно, а `F` — блокирующе (сейчас 0).

> ⚠️ **Не добавляйте `B` в `--select` командной строки.** `--select` в CLI
> **перебивает `ignore` из `pyproject.toml`**, и тогда возвращается `B008` —
> `Depends()` в аргументах функции, идиома FastAPI, которой в этом коде 98
> штук. Это не баг ruff, это его семантика; напоролись при установке.

```bash
make lint
```

Разбирать долг по одному правилу за раз:

```bash
uv run ruff check --select I --fix .
```

## 2. pyright — типы

Тайпчекера в проекте не было. Поставлен как отдельный инструмент (`uv tool`)
и как **LSP-плагин Claude Code** — тем же движком, так что то, что видит
редактор, совпадает с тем, что скажет `make types`.

```bash
make types
```

LSP даёт диагностику **пока код пишется**, а не после прогона. Плагин:
`pyright-lsp@claude-plugins-official`, стоит глобально.

## 3. Целостность ссылок на ассеты

`tests/frontend/test_asset_links.py`, 6 проверок, 0.05 s, никаких зависимостей.
Автоматизирует ловушки 7 и 8 из [CRITICAL-LINKS.md](CRITICAL-LINKS.md): битая
`url()` после удаления PNG и опечатка в имени кисти. Обе ломают страницу молча —
она не падает, просто теряет фон.

Проверяется 60 ссылок в 8 файлах плюс:
* все 15 кистей WASH лежат в `worte/`;
* **две копии карты WASH совпадают** — `js/words-data.js` (канон по `CLAUDE.md`)
  и фактическая копия в `js/wb-card.js:228`;
* голые имена файлов, к которым папка приклеивается в рантайме
  (`'roadmap-leaf-1.png'` + `'images/' +` в `schreiben.js`) — грепом такие не
  находятся.

Резолвит пути **как браузер**: из CSS — от папки стайла (отсюда грабли
`/css/worte/… → 404`), из HTML и JS — от корня сайта.

## 4. Визуальные снапшоты (Playwright)

```bash
make up          # снимки берутся с ЖИВОГО стека, не с файлов
make visual
```

5 снимков: Wörterbuch закрытый и с открытой карточкой, schreiben, pipeline,
шапка на мобильной ширине. Прогон ~20 s.

Эталоны — `tests/frontend/__snapshots__/`, они **в git**: это исходники
сравнения. Провалы кладутся в `tests/frontend/snapshot-failures/` (эталон, факт,
подсвеченный дифф) и в git не едут.

Перезаписать эталоны — **только посмотрев дифф**:

```bash
make visual-update
```

Живые числа (счётчики pipeline, таймер Pomodoro, статусы сохранения)
замаскированы: без этого тест падал бы каждый прогон.

> ⚠️ Эталоны сняты на macOS. В CI (Linux) они бы не совпали, поэтому там эти
> тесты **пропускаются сами** — фикстура `live_site` не находит nginx :8753.
> Это локальная сеть безопасности, а не gate на merge.

> ⚠️ Снимок `woerterbuch-open-card` зависит от содержимого базы: он берётся по
> реальному ответу `/api/vocab/search` на «Wirkung». Переобогатили карточку —
> перезапишите эталон.

## 5. Фаззинг API (Schemathesis)

Читает OpenAPI-схему, которую FastAPI генерит сам, и обстреливает каждую ручку.
Входит в `make test` (~1 мин). Глубже:

```bash
make fuzz
```

Разделён на две части намеренно:

* **`test_api_never_crashes_and_never_ignores_auth`** — gate. Две проверки:
  `ignored_auth` (повторяет запрос без учётных данных и требует отказа — ровно
  класс из коммитов «мутирующая ручка, открытая не тем») и `not_a_server_error`.
* **`test_api_responses_match_the_declared_schema`** — помечен `schema_debt` и
  из обычного прогона исключён, потому что **сейчас падает**. Смотреть
  осознанно: `make schema-debt`.

Часть ручек пропускается (`NEEDS_POSTGRES_OR_MISTRAL`): в SQLite-контуре они
500-ят по причинам окружения — `/api/vocab/search` построен на `pg_trgm`,
`analyze`-ручки требуют ключ Mistral. Список схлопнется, когда сюит поедет на
Postgres.

## 6. Покрытие внешнего корпуса

```bash
make coverage
```

Единственная метрика качества базы, которая меряется **не на самой базе**: 18
статей de.wikipedia по темам Goethe против лемм с готовой карточкой. Корпус
кэшируется в `backend/data/coverage-corpus/` (git-ignored), первый прогон тянет
его из сети.

Гонять после каждого вливания слов. Замер 26 июля: **63.0 % по токенам,
34.4 % по типам** на 92 090 карточках.

> ⚠️ С июльскими 72.3 → 76.4 % это **не сравнивать**: другой список статей и
> другая токенизация. Это новая базовая точка.

> ⚠️ Замер сверяет леммы, а не ходит в поиск, поэтому словоформы (`einem`,
> `wurde`) считаются промахом, хотя поиск находит их триграммами. «По типам»
> систематически занижено.

Скрипт **падает**, если в целевой БД ноль карточек: рядом с боевыми лежат
заглушки `app/vocab/*.db`, и без защиты он бы отчитался «0 %» вместо «читаю не
тот файл».

## 7. postgres-mcp — база в разговоре

`.mcp.json` подключает [postgres-mcp](https://github.com/crystaldba/postgres-mcp)
в режиме **restricted**: read-only на уровне транзакции плюс лимит времени
выполнения. Умеет ещё explain-план и подбор индексов — для `pg_trgm`-поиска
это в цель.

Зачем: `PLANS.md` целиком построен на замерах по живой базе, и каждый такой
замер сейчас — одноразовый скрипт, который потом теряется. Чем дешевле проверка
гипотезы, тем больше развилок закрывается до того, как в них вложились.

> ⚠️ Официальный `@modelcontextprotocol/server-postgres` **признан устаревшим в
> мае 2025 из-за SQL-инъекции**. Не подключать его.

> ⚠️ `restricted` — не замена правам. Сильнее было бы завести отдельную
> read-only роль в Postgres:
> ```sql
> CREATE ROLE claude_ro LOGIN PASSWORD '...';
> GRANT USAGE ON SCHEMA public TO claude_ro;
> GRANT SELECT ON ALL TABLES IN SCHEMA public TO claude_ro;
> ```
> и поменять строку подключения в `.mcp.json`.

## Хуки — что срабатывает само

Настроены в `.claude/settings.json`, скрипты в `scripts/hooks/`.
`.claude/settings.json` **отслеживается в git** намеренно (в `.gitignore` для
него сделано исключение): хуки — часть конфигурации проекта.

| хук | когда | что делает |
|---|---|---|
| `ruff-on-edit.sh` | правка `*.py` | ruff `F` по этому файлу; нашёл — блокирует и требует починить |
| `frontend-on-edit.sh` | правка `*.html/css/js` | прогоняет тест ссылок; для css/js показывает текущий `?v=` |
| `docker-guard.sh` | любая Bash-команда | на `docker down/restart`, `make up/down/clean` — **спрашивает**, напоминая, что рестарт убивает воркеров обогащения |
| `stop-checks.sh` | конец сессии | если трогали фронт/Python — быстрые проверки; сломано → не даёт закончить |

Устройство намеренное:

* **`docker-guard` спрашивает, а не запрещает.** Docker тут нужен постоянно;
  запрет сделал бы хук вредным. Запрос показывает цену в момент решения.
* **`stop-checks` гоняет только быстрое** (~2 s). `make test`, снапшоты и
  фаззинг там были бы правильны по смыслу и убийственны на практике — хук с
  минутной паузой выключают. Про них он напоминает текстом.
* **Зацикливания нет**: `stop-checks` смотрит `stop_hook_active` и второй раз
  подряд не блокирует.

Выключить временно — закомментировать блок в `.claude/settings.json`.
Проверить хук руками:

```bash
echo '{"tool_input":{"file_path":"backend/app/vocab/dsl.py"}}' | ./scripts/hooks/ruff-on-edit.sh
```

## Что нашлось при установке

Инструменты окупились до того, как их дописали:

1. **`OverflowError` на числе в пути > int64** → 500 вместо 404/422, на всех
   ручках с числовым параметром. Нашёл Schemathesis.
2. **`guest_expires_at` без часового пояса** в `/api/auth/me` — схема объявляет
   RFC 3339, где смещение обязательно. Нашёл Schemathesis.
3. **Карта WASH продублирована** — `CLAUDE.md` называет `words-data.js`
   единственным источником, копия живёт в `wb-card.js:228`.
4. **Тест, который не проверял то, что обещал** — `test_enrich.py:85` собирал
   `remaining` и не смотрел в него. Нашёл ruff (F841), проверка дописана.
5. **Самых частотных слов немецкого нет в базе** — `ist`, `eine`, `wird`,
   `sind`, `hat`, `war` возглавляют список промахов. Независимо подтверждает
   пункт A1 аудита.

Подробности и статус — в [PLANS.md](PLANS.md).
